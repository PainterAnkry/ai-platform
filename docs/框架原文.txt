面向软件工程师求职的 Coding Agent 项目开发框架

一、项目定位

开发一个前后端分离的 AI 智能知识库 + Agent 工作流平台，用于展示 Vue/JavaScript、Python
FastAPI、HTTP/API、异步任务、RAG、Agent、MCP、模型服务与 Docker
部署等综合工程能力。项目以“真实可运行、架构清晰、方便面试演示”为核心目标，而不是简单堆砌技术栈。

七、RAG 知识库流程

文档处理：

用户上传文件 → 创建异步 Task → Worker 解析 PDF/Word/TXT → 文本清洗 → 文本切片 → Embedding → pgvector →
任务完成。

知识问答：

用户问题 → Query Embedding → Top-K 向量检索 → Reranker → 构造 Prompt → LLM → SSE 流式返回答案与来源。

RAG 返回结果应包含文档名称、页码或其他可定位信息，避免只给出没有来源的模型回答。

八、Agent 工作流

用户问题
!“
Agent 判断任务
├── 普通问答
├── 知识库检索
├── 数据分析
├── MCP 工具
└── HTTP API
!“
Tool 执行
!“
Tool Result
!“
Agent 再次决策
!“
最终答案

前端实时展示 Agent 执行步骤，例如：分析用户意图 → 查询知识库 → 找到相关资料 → 调用工具 → 生成最终答案。

九、数据分析 Agent

支持用户上传 Excel/CSV 后，由 Agent 判断是否需要数据分析，并通过 Pandas 完成数据清洗、统计分析，再使用
Matplotlib 生成图表，最后由 LLM 生成自然语言分析结论。

示例：上传
sales.xlsx，询问“分析今年各月份销售趋势，并找出异常月份”，系统自动完成读取、分析、绘图与总结。

十、MCP 设计

自建 MCP Server
├── calculator
├── knowledge_search
├── weather
├── http_request
└── python_analysis

Agent 根据任务自动选择 MCP Tool，并将工具结果重新交给 Agent 继续推理。MCP
模块应独立于业务代码，方便后续增加第三方工具。

十五、给 Coding Agent 的开发原则

• 不要一次性生成整个项目，每完成一个 Phase 先保证项目可运行。

• 不要为了体现技术栈而无意义增加依赖，优先保证稳定和可维护性。

• 前后端接口明确，使用 OpenAPI/Swagger 管理 API。

• 后端采用 API/Controller、Service、Repository、Model 等清晰分层。

• 所有配置通过 .env 管理，禁止把 API Key、数据库密码写死。

• LLM 使用 Provider 抽象层，不绑定单一模型厂商。

• AI 流式输出优先使用 SSE。

• 文档解析、Embedding 等耗时任务必须进入异步 Worker，不阻塞 FastAPI 主线程。

• RAG、Agent、MCP 必须独立模块化，避免严重耦合。

• 核心功能加入异常处理、日志和基本测试。

• 数据库结构修改统一使用 Alembic Migration。
